# หมาล่าทอด — ระบบสั่งจองคิว (เก็บข้อมูลบนเครื่องเราเอง)

ระบบนี้แยกเป็น 2 ส่วน:
- **server.js** — เซิร์ฟเวอร์ Node.js (ไม่ต้องลง library เพิ่ม ใช้ของในตัว Node ล้วนๆ) ทำหน้าที่เก็บข้อมูลทุกอย่างไว้ในโฟลเดอร์ `data/` บนเครื่องที่รันโค้ด
- **public/index.html** — หน้าเว็บ (ทั้งฝั่งลูกค้าและหลังบ้าน) ที่คุยกับ server.js ผ่าน API

## วิธีรัน

ต้องมี [Node.js](https://nodejs.org) ติดตั้งในเครื่อง (เวอร์ชัน 18 ขึ้นไป) แค่นั้นพอ ไม่ต้อง `npm install` ใดๆ

```bash
node server.js
```

จากนั้นเปิดเบราว์เซอร์ไปที่ `http://localhost:3000` (หรือเครื่องอื่นในวงแลนเดียวกันเปิดผ่าน `http://<ไอพีเครื่องนี้>:3000`)

รหัส PIN เข้าหลังบ้านเริ่มต้นคือ `1234` (ไปเปลี่ยนได้ในแท็บ "ตั้งค่าร้าน" หลังเข้าระบบ)

## ข้อมูลเก็บไว้ที่ไหน

พอรันครั้งแรก ระบบจะสร้างโฟลเดอร์ `data/` ให้เองอัตโนมัติ (ถ้ายังไม่มี) โครงสร้างเป็นแบบนี้:

```
data/
  settings.json   ← ชื่อร้าน, รูป QR, รหัส PIN
  stock.json      ← จำนวนของที่เหลือของแต่ละเมนู
  orders.json     ← ออเดอร์ทั้งหมด
  counter.json    ← ตัวนับเลขคิว
  uploads/        ← รูปสลิปโอนเงินของลูกค้า + รูป QR ร้าน
```

ข้อมูลทั้งหมดอยู่ในไฟล์ธรรมดา แม้ปิดเซิร์ฟเวอร์หรือรีสตาร์ทเครื่อง เปิดใหม่ข้อมูลก็ยังอยู่ครบ อยากสำรองข้อมูลก็แค่ copy โฟลเดอร์ `data/` ทั้งก้อนไปเก็บไว้ที่อื่นได้เลย (หรือใช้ปุ่ม "ดาวน์โหลดไฟล์สำรองเต็ม" ในหลังบ้านก็ได้เหมือนเดิม)

## ระบบสต็อกแบบเรียลไทม์

- หลังบ้าน → แท็บ **"สต็อกสินค้า"**: ใส่จำนวนไม้ที่เหลือของแต่ละเมนู หรือกดปุ่ม **+ / −** ข้างช่องกรอกเพื่อปรับทีละ 1 ก็ได้ แล้วกด "บันทึกจำนวนคงเหลือ" (ปล่อยช่องว่างไว้ = ไม่จำกัดจำนวน)
- หน้าลูกค้าจะเห็นป้าย "เหลือ N" ที่แต่ละเมนู และตัวเลขจะอัปเดตทันทีแบบเรียลไทม์ (ผ่าน Server-Sent Events) โดยไม่ต้อง refresh หน้าเว็บ — ถ้าของหมด ปุ่ม "+" จะกดเพิ่มไม่ได้และขึ้น "หมดแล้ว"
- ระบบกันไม่ให้สั่งเกินจำนวนที่เหลือจริง แม้จะมีคนสั่งพร้อมกันหลายคน (เช็คและตัดสต็อกที่ฝั่งเซิร์ฟเวอร์เสมอ)

## รูปสินค้าและโลโก้ร้าน (แทนอิโมจิ)

หลังบ้าน → แท็บ **"ตั้งค่าร้าน"**:

- **โลโก้ร้าน**: อัปโหลดแทนไอคอน 🍢 ที่หัวเว็บได้ — แนะนำรูปสี่เหลี่ยมจัตุรัส ขนาด **200×200 พิกเซล** (พื้นหลังโปร่งใสได้) ไฟล์ .png หรือ .jpg ไม่เกิน 1MB
- **รูปสินค้า**: อัปโหลดรูปแทนอิโมจิของแต่ละเมนูได้ทีละรายการ — แนะนำรูปสี่เหลี่ยมจัตุรัส ขนาด **300×300 พิกเซล** (อัตราส่วน 1:1) ไฟล์ .jpg หรือ .png ไม่เกิน 1MB ต่อรูป ระบบจะย่อ/บีบอัดให้อัตโนมัติก่อนอัปโหลดอยู่แล้ว ถ้าไม่ได้อัปโหลด เมนูนั้นจะยังแสดงอิโมจิเดิม
- กดปุ่ม "ลบ" ข้างรูป เพื่อกลับไปใช้อิโมจิ/ไอคอนเดิมได้ตลอด

## แจ้งเตือนออเดอร์ใหม่แบบเรียลไทม์ (หลังบ้าน)

พอลูกค้ากด "ยืนยันคำสั่งซื้อ" หน้าหลังบ้านจะขึ้นทันทีโดยไม่ต้อง refresh หน้าเว็บเลย:

- **ป๊อบอัพแจ้งเตือน**: ขึ้นมุมบนของจอ บอกเลขคิว ชื่อ/ห้องลูกค้า รายการที่สั่ง และยอดชำระ กดที่ป๊อบอัพเพื่อไปดูรายการ หรือกด ✕ เพื่อปิด (ถ้าไม่กดอะไรจะหายไปเองใน 8 วินาที)
- **เสียงแจ้งเตือน**: เสียง "ติ๊ง" ดังขึ้นทุกครั้งที่มีออเดอร์ใหม่เข้ามา ไม่ว่าจะอยู่แท็บไหนในหลังบ้านก็ได้ยิน — มีปุ่ม 🔔/🔕 มุมขวาบนของหลังบ้านไว้เปิด-ปิดเสียงได้ตามใจ (จำค่าไว้ให้ในเครื่องนั้นๆ)
- **จุดไข่ปลาสีทอง**: ขึ้นเตือนที่แท็บ "รายการสั่งซื้อ" ด้วย เผื่อพลาดป๊อบอัพ
- ถ้าเบราว์เซอร์อนุญาต จะมีการแจ้งเตือนแบบ desktop notification โผล่ให้ด้วยเวลาเปิดแท็บอื่นค้างไว้ (ไม่บังคับ ขึ้นอยู่กับที่เบราว์เซอร์อนุญาต)

## เปิดให้ลูกค้าในหอ/ในร้านเข้าจากมือถือ

รันคำสั่ง `node server.js` บนคอมเครื่องเดียวที่เชื่อมกับ Wi-Fi เดียวกับลูกค้า แล้วดูไอพีเครื่องนั้น (เช่น `192.168.1.23`) ให้ลูกค้าเปิด `http://192.168.1.23:3000` จากมือถือได้เลย ทุกคนจะเห็นสต็อกและคิวเดียวกันแบบเรียลไทม์

## บันทึกรูปใบเสร็จลงเครื่อง

ปุ่ม "บันทึกรูปใบเสร็จ" (ในหน้ายืนยันคำสั่งซื้อ และหน้าเช็คสถานะ) ตอนนี้ลองบันทึกด้วย 3 วิธีเรียงลำดับ เพื่อให้ใช้ได้จริงบนมือถือทุกรุ่น:

1. เปิดหน้าต่างแชร์ของเครื่อง (share sheet) ให้เลือก "บันทึกภาพ" ได้เลย — ใช้ได้บน iOS/Android รุ่นใหม่ที่เข้าเว็บผ่าน HTTPS
2. ถ้าเครื่องไม่รองรับ share sheet (เช่นเข้าเว็บผ่าน `http://` ในวงแลน): เครื่อง Android/คอมพิวเตอร์จะดาวน์โหลดไฟล์ลงเครื่องให้อัตโนมัติ
3. บน iPhone/iPad ที่ดาวน์โหลดอัตโนมัติไม่ได้ (ข้อจำกัดของ Safari) ระบบจะเปิดรูปใบเสร็จแบบเต็มจอ พร้อมข้อความบอกให้ **กดค้างที่รูปแล้วเลือก "บันทึกลงในรูปภาพ"** ซึ่งบันทึกได้แน่นอน 100%

## หมายเหตุ

- ปุ่ม "ดาวน์โหลด Excel/JSON สำรอง" และ "กู้คืนจากไฟล์สำรอง" ในหลังบ้านยังใช้งานได้เหมือนเดิม แต่ตอนนี้ข้อมูลต้นทางคือไฟล์บนเครื่องแทนที่จะเป็นระบบเก็บข้อมูลของ Claude
- ต้องเปิด server.js ทิ้งไว้ตลอดเวลาที่ต้องการให้เว็บใช้งานได้ (จะรันเป็น background service ต่อก็ได้ด้วยเครื่องมือเช่น `pm2` หากต้องการให้รันถาวร)
